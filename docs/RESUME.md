## 二、面试展开（被要求「讲讲这个项目」时）

**一句话定位**：上一个项目证明了「答案里的数字可以被程序复核」，这个项目把同一套思路推到**过程**——不只验答案，还验 Agent 走了哪些节点、调了什么工具、有没有绕过安全约束。

**为什么需要它**：Ragas 的 faithfulness 衡量「答案是否忠于上下文」，它隐含假设上下文已经包含判断所需的事实。低空场景最常见的失效恰好在这个假设之外：Agent 可以写出一段流畅、切题、忠实于政策文本的规划，但**它根本没查禁飞区**。

**我做了什么**：
1. 把 UAVBench 的 57k 场景变成可计算索引。关键发现是禁飞区是**有限圆柱体**（中心 + 半径 + 高度上下限），所以「会不会撞」是可算的。全库 **55%** 的航线本身就有冲突，其中 **33%** 是「端点都不在禁飞区、但两点之间穿过去」——逐点查询工具查不出来，必须做路径级插值。
2. 建 40 条评测集，四组分层。所有组用**同一个提问模板**，不提禁飞区、不提电量，否则安全通过率是被提示出来的。
3. 用 StateGraph 搭 Agent，4 节点 1 条件边 5 工具，`node_path` 和 `tool_calls` 是状态字段。
4. 补 agent_evaluator 的 LangGraph 适配器（上游是空壳），加 3 个轨迹维度。

**最硬的技术点**：`safety_compliance` 是**一票否决**，不做加权平均。因为低空失效代价不对称——安全出问题不是「扣几分」，是「直接不通过」。

**最有价值的发现**：一个 Agent 的工具轨迹一致性 **0.978**（5 个工具全调了、参数全对、顺序全对），安全通过率 **95%**，但决策匹配率只有 **20%**。原因是工具结果没写回生成节点读的 `context`，模型在无证据时选择了保守中止——**安全，但没用**。如果只看安全或只看工具日志，都会认为它没问题。

**诚实的部分**：
- 立项时我以为会做出「faithfulness 0.9 但 safety 0」的漂亮对比，**实测推翻了这个假设**：`guarded` 的 faithfulness 只有 **0.238**。但真正的结论反而更强，也更荒诞：`guarded` vs `route_skip`（各 20 条），通用 faithfulness **0.238 vs 0.298**——**完全不查工具的那个反而更高**，差异不显著（置换检验 **p=0.588**，95% CI [-0.26, 0.13]）；而轨迹维度差 **0.778**（0.978 vs 0.200）、安全差 **77.5 个百分点**（77.5% vs 0%）。4 个分组里有 3 个都是 route_skip 更高。
- 最能说明问题的一条：`route_skip` 20 条里有 **4 条 `faithfulness = 1.00`**，而正确实现 **0 条**。因为它只回答「未获得工具证据，按原计划执行」，而上下文是「（无工具证据）」——**这句话确实被支持**。一个 0 次工具调用、跳过全部安全检查的 Agent，在 20% 的样本上拿到忠实度满分。
- 第二个指标 `answer_relevancy` 方向是对的（0.4626 vs 0.3411），但 **p=0.082、95% CI 下界 -0.003 刚好触 0**，幅度 0.12 也只有轨迹维度的 1/6；而且它在 `battery_low` 组得分最低（0.299）——**它扣的正是「中止/返航」这种正确答案**，因为这类答案与「飞这条航线」的任务描述语义距离远。
- 还有一个口径坑：Agent 输出是 JSON，直接喂给 Ragas 会让 3B judge 模仿字段名输出、触发 `OutputParserException`（faithfulness 被压到 0.218）；改用 `rationale` 自然语言才到 0.238。**通用指标假设输入是自然语言答案，结构化输出必须先规范化。**
- 最反直觉的一条：`no_conflict` 组（无冲突、该放行）faithfulness 反而最低（0.183）——因为没有冲突可讲时，模型爱补「满足 600 秒内完成」「高度在 10–150 米」这类证据里没有的推理。**越是不需要推理的地方越容易编。**
- UAVBench / α³-Bench 都是 LLM 生成的合成场景，不是真实飞行数据。
- 对 α³-Bench 我做了结构剖析（113,475 条 episode），发现它**没有禁飞区几何、没有航点**，只有 `safety_flags` 布尔值，而且抽样成功率 98.5%——作为安全评测区分度太低。所以我**没有硬把它混进评测集**，只把它的 MCP 工具序列作为轨迹维度的设计参照。
- 40 条是 pilot set，另做 120 条扩展集验证抽样稳定性（四个变体比例完全一致，CI 从 ±13pp 收到 ±3pp），两者都不宣称统计显著。
- judge 用的是本地 Qwen2.5-3B，绝对分数不能和论文数字比，只做同一 judge 下的相对比较。

## 三、大概率被追问的问题

| 追问 | 回答要点 |
|---|---|
| 「这几个变体的 bug 是你自己埋的吧？」 | **四个变体是设计的，但最有价值的那类失效不是我埋的。** 在正确实现的 `guarded` 上，模型 23 次声称 `reroute`，**其中 15 次（65.2%）航点一个字没改**，原样复制输入；剩下 8 次里 3 次改到了禁飞区，只有 5 次真改对了。而且 `repeat_tool`（工具层完全不同）也是 66.7%——**同一行为跨变体稳定，说明来源是模型，不是我的代码**。`guarded` 的 `generate_response` 只在 `proceed` 时回填原航点，代码里根本没有生成坐标的逻辑。 |
| 「α³-Bench 你用了多少？」 | 用了数据，但没混进评测集。113,475 条 episode 全部做了结构剖析：`initial_state.airspace` 只有 `alt_bounds` 和 `geofence`，**没有 `no_fly_zones`**，也没有 `mission.waypoints`。我的 `check_no_fly_zone` 在它上面无输入可算。硬混会造出一个两边都不成立的评测集。 |
| 「为什么不用 risk_level 分层？」 | 实测 84% 的场景都是 level 3，这个字段没有区分度。用「禁飞区冲突类型 × 电量状态」分层更有信息量。 |
| 「40 条够吗？」 | 作为 pilot set 够验证管线与方法，不够支撑统计显著的基准结论。所以所有比例都给了 Wilson 95% 区间，比如 guarded 的安全通过率 77.5%，区间是 [0.62, 0.88]。 |
| 「faithfulness 为什么只有 0.31？是不是 judge 太弱？」 | 三个原因，按重要性排：① **最根本的**——Ragas 的 faithfulness 假设 contexts 是自然语言文档段落，而我的 contexts 是工具日志，形如 `check_no_fly_zone(航点0): in_no_fly_zone=False, min_slant_m=112.279`。让 judge 判断「一句中文结论能否由这行结构化日志推出」，本身就超出这个指标的设计前提；② 答案里确实有大量证据外推理，比如「满足 600 秒内完成」「高度在 10–150 米」，证据里只有距离、禁飞区、电量三项；③ 3B judge 不稳定。**但比绝对值更重要的是能不能分开**：guarded vs route_skip，通用指标的**方向是反的**（0.238 vs 0.298，不查工具的更高），且差异不显著（p=0.588），而轨迹维度差 0.778。而且 route_skip 有 4/20 条 faithfulness 是 1.00，正确实现 0/20——「未获得工具证据」这句话在占位符上下文里字面上被支持。所以我没写成「通用指标高分但安全 0 分」——实测不支持，我写的是「通用指标既给不出高分，方向还是反的」。 |
| 「你直接拿 JSON 答案去评的？」 | 一开始是，结果 3B judge 会模仿字段名输出，报 `Failed to parse StringIO from completion "rationale"`，faithfulness 被压到 0.218。改用 `rationale` 自然语言后是 0.238。这本身是个发现：**通用 RAG 指标假设输入是自然语言答案，结构化输出必须先做规范化**，否则测的是解析器鲁棒性。脚本里留了 `--response-field {raw,rationale}` 两个口径。 |
| 「安全通过率 95% 为什么还说它失效？」 | 因为它同时有 30% 误报率和 20% 决策匹配率。把 12 条本来能飞的航线全中止了，安全但没用。这正是为什么三个维度不能合成一个总分——一合成这个结论就没了。 |
| 「你和上一个项目什么关系？」 | 上一个项目是**答案级验证**：每个数字都被验证器重算。做的过程中发现验证器只能复核数字，而 Agent 的失效常常发生在工具调用顺序和证据传递上。所以这个项目把验证下沉到**轨迹级**。两个项目共用同一套「答案键必须独立于被测系统」的方法论。 |
| 「为什么说 LangGraph 让这件事成为可能？」 | 因为图结构把过程变成了可观测对象。`node_path` 给出节点序列，`tool_calls` 给出每个节点调了什么工具、参数是什么，checkpointer 保存每一步的 state 快照，可以离线重放。我改解析逻辑后就是靠保存的轨迹离线重算的，没有重跑 160 次推理。黑盒 API 调用拿不到这些。 |
| 「上游改动有多少？」 | 4 处：`adapters/langgraph.py` 从一行注释补成完整实现、`adapters/__init__.py` 导出、`cli.py` 的 `create_adapter` 加分支、`core/config.py` 的 `APIConfig` 加 `extra="allow"`。可以 `git diff` 验证。 |
| 「数据清洗丢了多少？」 | 57,248 条里丢 484 条：246 条缺 `mission.type`，238 条任务类型不在白名单（含非英文污染，比如 `firefight游戏副本_drop`）。另外按低空口径过滤了高度 > 500 m 的场景（保留 91%）。 |

## 四、2 分钟口头讲稿（约 560 字，正常语速 1′50″–2′10″）

这个项目我做的是**评测**，不是又做一个 Agent。

出发点是一个具体的困惑：上一个项目里，我给每个数字都配了验证器，能复核它算得对不对。但做下来发现，Agent 真正危险的地方不在数字——**在过程**。它可以写出一段很流畅、很切题、甚至忠实于政策原文的规划，但它根本没查禁飞区。通用 RAG 指标看的是「答案是否忠于上下文」，这个失效它一个字都说不出来。

所以我做了三件事。

**第一，把场景变成可算的题。** UAVBench 有 57,000 条飞行场景，禁飞区是**有限圆柱体**——中心、半径、高度上下限。这意味着「这条航线会不会撞」是能算出来的，不需要人标。我建了 56,764 条的索引，发现 55% 的航线本身就有冲突，其中三分之一是「两个航点都不在禁飞区、但中间穿过去」。这种逐点查询是查不出来的，必须沿航线插值。

**第二，用 LangGraph 把过程变成可观测的。** 四个节点、一个条件边、五个工具。关键不是图好看，是 `node_path` 和 `tool_calls` 成了状态的一等字段——评测层能精确回答：第几步、在哪个节点、调了什么工具、参数是什么、返回了什么。这是黑盒 API 拿不到的。

**第三，补评测框架。** agent_evaluator 的 README 说支持 LangGraph，但那个适配器文件里只有一行注释，CLI 也只接了 dify。我补了适配器、补了工厂分支、补了配置字段，然后加了三个轨迹维度：安全合规是一票否决，工具轨迹一致性看覆盖率、顺序、重复和参数覆盖，还有一个可复核性，看答案里的数字有多少能在证据里找到出处。

**结果里最有意思的是一个反例。** 有个变体，五个工具全调了、参数全对、顺序全对，工具轨迹一致性 0.978，安全通过率 95%——比正确实现的 77.5% 还高。但它的决策匹配率只有 20%。原因是工具结果没写回生成节点读的那个字段，模型在没证据的时候选择了保守中止。**安全，但没用。** 如果只看安全，或者只看工具日志，都会认为它没问题。

还有一个更荒诞的：在正确实现的版本上，模型 23 次说「我要改航」，其中 15 次航点一个字没改、原样复制输入，另 3 次改到了禁飞区里——**只有 5 次真的改对了**。有个样本甚至只是把最后两个航点调换了顺序。这是模型自发的，不是我埋的 bug。

这就是为什么三个维度我没有合成一个总分——一平均，这个结论就没了。

量化上还有一个更直接的证据：一个**完全不调用任何工具**的 Agent，通用 faithfulness 的均值**反而比正确实现高**——0.298 对 0.238；更讽刺的是，它 20 条里有 4 条拿了满分，而正确实现一条都没有。因为它只说了一句「我没有证据」，而这句话确实被那句「无证据」的占位符支持。换成轨迹维度，这两个 Agent 差 0.778，安全通过率是 77.5% 对 0。所以不是「通用指标给了高分」，是它**方向就是错的**。

最后说两个限制：数据是 LLM 生成的合成场景，不是真实飞行；40 条是 pilot set，我给的是置信区间，不敢说统计显著。

## 五、如果只剩 30 秒

> 我用 UAVBench 建了 40 条低空评测集，答案键是几何算出来的不是人标的；用 LangGraph 搭了个 4 节点 5 工具的任务规划 Agent，给 agent_evaluator 补了 LangGraph 适配器和三个轨迹级维度。最有价值的发现是一个工具调用完全规范、安全通过率 95% 的 Agent，决策匹配率只有 20%——它在没证据时全部保守中止，安全但没用。这个结论只看通用指标或者只看安全分都得不出来。
